## Phase Goal

**As a** customer browsing a product, **I want to** enter my pincode on the product page and see the estimated shipping cost, delivery time, and whether cash-on-delivery is available for that product, **so that** I can judge the true delivery cost and timeline before any cart or checkout exists.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `delivery-estimate` Edge Function | Untrusted user-entered pincode + Turnstile token cross here |
| browser → localStorage | Persisted pincode value read back on load |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | pincode input → estimateDelivery | mitigate | Validate `/^\d{6}$/` inline before any network call (D-02); the Edge Function re-validates server-side (`bad_request` 400) — client check is defense-in-depth, not the boundary |
| T-07-02 | Spoofing/DoS | estimate invoke abuse | mitigate | Turnstile-gated single-use token per lookup (D-01); server-side siteverify with the secret held only in the function env; the block resets the widget after every invoke so no token replay |
| T-07-03 | Information disclosure | localStorage pincode | accept | A 6-digit pincode is non-sensitive (no PII, no auth material); localStorage is the intended cross-page store (D-11) shared with Phase 8 |
| T-07-04 | Tampering | localStorage value re-read as pincode | mitigate | The prefilled value is re-validated `/^\d{6}$/` before use and rendered as text only (no HTML injection surface); a tampered value cannot escalate |
| T-07-SC | Tampering | client dependencies | mitigate | No npm installs in this phase — Turnstile loads via the existing hosted-CDN loader; `@marsidev/react-turnstile` is explicitly forbidden. No package legitimacy gate required |
</threat_model>
