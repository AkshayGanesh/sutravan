# Phase 7 — UI Design Contract

> Visual and interaction contract for the per-product delivery estimate block inside the ProductDetail modal. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** the "Delivery" section rendered inside `client/src/components/ProductDetail.tsx` (a shadcn `Dialog` modal — NOT a page), between the price/variant selector (~L193–204) and the "Enquire on Instagram" CTA (~L320). The shared `DeliveryProvider`/`useDelivery`/`useDeliveryEstimate` layer is headless and carries no visual contract beyond persisting the pincode.

## Spacing Scale

The codebase uses the Tailwind default 4px scale. Multiples of 4 only.

| Token | Value | Usage in this block |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gaps (`gap-1`), micro margins |
| sm | 8px | Input↔button gap, chip padding (`gap-2`) |
| md | 16px | Block outer margin from siblings (`mt-4`), result panel padding (`p-4`) |
| lg | 24px | Right-column container padding (`p-6`, inherited from parent) |

Section separation: the Delivery block opens with a top divider matching the existing shelf-life section — `mt-4 pt-4 border-t border-border/50` (see ProductDetail L298). Result numbers sit in an inset panel padded at 16px.

Exceptions:
- Primary button vertical padding is `py-3` (12px) to visually match the existing luxury CTA rhythm (existing Instagram CTA uses `py-3.5`/14px; the Check-delivery button is secondary in weight so `py-3`/12px is the intentional step down). 12px is a multiple of 4 — no true exception.
- Touch targets: input and button must be ≥44px tall on mobile (input default h-9=36px is acceptable inside the modal but bump the button to `py-3` so the tap target clears 44px).

## Typography

Declared for this block, mirroring ProductDetail's established hierarchy. Sizes map to Tailwind `text-xs/sm/xl`.

| Role | Size | Weight | Line Height | Applied to |
|------|------|--------|-------------|------------|
| Section label | 12px (`text-xs`) | Semibold 600 | 1.4 | "DELIVERY" heading — uppercase, `tracking-widest`, `text-foreground/50` (matches Benefits/Ingredients headings) |
| Body / helper | 14px (`text-sm`) | Regular 400 | 1.5 | ETA line, COD line, disclaimer/provisional/free-ship notes (`text-foreground/70–80`) |
| Fine print | 12px (`text-xs`) | Regular 400 | 1.5 | "Estimated — final may vary", "working days excl. weekends & holidays (IST)" (`text-foreground/50`, italic where it matches sibling captions) |
| Cost figure | 20px (`text-xl`) | Semibold 600 | 1.2 | The `₹X` estimated-cost number (matches the price line at L193) |

**Two primary weights:** Regular 400 (body/notes) + Semibold 600 (section label, cost). Exception: the button label uses Medium 500 `uppercase tracking-wider` to match the established CTA convention in this component — inherited pattern, not a new decision.

Do NOT use `--font-serif` (Samarkan) anywhere in this block.

## Color

The theme is a warm earthen palette. 60/30/10 split expressed via existing tokens:

| Role | Token / Value | Usage |
|------|--------------|-------|
| Dominant (60%) | `--background` `hsl(40 33% 96%)` light beige | Block sits on the modal's right-column `bg-background` |
| Secondary (30%) | `--muted` `hsl(38 20% 85%)` / `--card` sandalwood `hsl(38 44% 85%)` | The result inset panel uses `bg-muted/40` (or `bg-card`) to make the estimate prominent (SC4) and visually distinct from surrounding copy |
| Accent (10%) | `--secondary` gold `hsl(43 65% 60%)` | See reserved list below |
| Action | `--primary` forest green `hsl(146 32% 24%)` | The "Check delivery" button fill (`bg-primary text-primary-foreground`), consistent with every CTA in the app |
| Destructive | `--destructive` `hsl(0 84% 60%)` | Inline invalid-format error text and the fetch-failure error message ONLY |

**Accent (gold `--secondary`) reserved for:** (1) the COD-available affirmative icon/text emphasis, (2) the "Free delivery over ₹X" messaging highlight when a threshold is set, (3) the focus ring on the pincode input (`--ring` is already gold). Never used as a fill for buttons or large surfaces.

**Note on "primary vs accent":** forest green (`--primary`) is the brand action color and carries the button; gold (`--secondary`) is the sparing accent. Do not swap these — the button must be green to match every other CTA in ProductDetail.

Radius: `--radius: 0rem` — all elements in this block are sharp-edged (no rounded corners), matching the luxury/earthen aesthetic. Do not add `rounded-*` classes except the existing dot-indicator pattern.

## Copywriting Contract

All copy below is the locked wording for this phase (CONTEXT.md delegated exact wording to this UI-SPEC; `<decisions>` D-04–D-07, D-13 set the required framing). Keep it plain, warm, and honest — an estimate, never a promise.

| Element | Copy |
|---------|------|
| Section heading | `DELIVERY` (uppercase, styled like Benefits/Ingredients) |
| Prompt (pre-check idle state) | `Enter your pincode to estimate delivery cost, time & COD.` |
| Input placeholder | `6-digit pincode` |
| Primary CTA | `Check delivery` |
| Primary CTA (retry after failure) | `Try again` |
| Invalid format (inline, no network call) | `Enter a valid 6-digit pincode.` |
| Non-serviceable result | `Sorry, we don't deliver to this pincode yet.` |
| Fetch failure | `Couldn't get an estimate right now. Please try again.` (with the retry button) |
| Cost line | `₹{X}` (integer, thousands-separated via `formatPrice`; engine already rounded — NO UI rounding) |
| Cost disclaimer (inline, always with a result) | `Estimated — final delivery charge may vary.` |
| ETA line | `Arrives in {min}–{max} working days` |
| ETA sub-caption | `Working days, excluding weekends & holidays (IST).` |
| COD available | `Cash on delivery available` |
| COD unavailable | `Cash on delivery not available for this pincode` |
| Provisional banner (`originConfigured: false`) | `Delivery estimates are provisional and will be finalized shortly.` |
| Free-shipping (only when `delivery_free_ship_threshold` is set — hidden today) | `Free delivery on orders over ₹{X}.` |

**Destructive actions:** none in this phase. No confirmation dialogs required.

Copy rules:
- Always show the cost disclaimer adjacent to any `₹` figure — the estimate must never read as a guaranteed charge (DLVR-07 / SC4).
- When `originConfigured` is false, still render the numbers AND the provisional banner above/around them (D-07). Never hide the estimate.
- ETA must be framed as a working-days range, never a single day or a calendar date (calendar dates are deferred to DLVR-F3).

## Interaction States (SC3 / DLVR-06)

Five distinct, visually separable states. The block is always visible (no collapse, D-03).

| State | Trigger | Visual |
|-------|---------|--------|
| Idle / pre-check | Modal open; saved pincode prefilled but no result yet (D-08) | Prompt copy + input (prefilled) + "Check delivery" button. Managed Turnstile widget mounted, invisible. No result shown. |
| Invalid format | Input fails `/^\d{6}$/` on button press (D-02) | Inline `text-destructive` message under the input. No network call, no skeleton. |
| Loading | Valid pincode → invoke in flight | `Skeleton` (`@/components/ui/skeleton`) rows mirroring the final result layout (cost line + ETA line + COD line) — no layout shift. Button shows a disabled/pending state. |
| Result — serviceable | `serviceable: true` | Inset `bg-muted/40` panel: cost figure (20px semibold) + disclaimer, ETA line + sub-caption, COD yes/no line. Provisional banner if `originConfigured: false`. Free-ship line if threshold set. |
| Result — non-serviceable | `serviceable: false` | Clean single-line message (no cost/ETA panel). Input stays editable for a re-check. |
| Fetch failure | network/timeout/5xx, or `captcha_failed` (400) | `text-destructive` error line + the CTA relabeled `Try again` (re-press re-solves Turnstile and re-invokes). Map `bad_request` (400) → treat as invalid-format inline instead. |

Error-code mapping (from the deployed function contract, per D-13):
- `bad_request` (400) → invalid-format inline message (no retry framing)
- `captcha_failed` (400) → fetch-failure with retry
- network / timeout / 5xx → fetch-failure with retry

Prefill behavior (D-08): the saved localStorage pincode prefills the input on open, but the result stays hidden until an explicit "Check delivery" press — so no Turnstile/network fires on every modal open.
