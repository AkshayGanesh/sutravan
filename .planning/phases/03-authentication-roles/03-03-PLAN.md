Deliver the core customer auth slice end-to-end: register (`/register`), login (`/login`), session persistence, and logout from any page via a Navbar account menu (D-09). ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form -> Supabase Auth | Untrusted credentials/registration input crosses here; GoTrue validates. |
| login redirect target -> client navigation | A `next`/returnTo value is untrusted input that must not enable open redirect. |
| customer JWT -> public.profiles / catalog (PostgREST) | The real enforcement boundary; exercised by the manual AUTH-04 escalation proof. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-06 | Information Disclosure | login/register error copy reveals which factor failed | mitigate | `mapAuthError` returns a single generic credentials message (D-14); no pre-flight email-exists check. |
| T-3-10 | Spoofing | open redirect via `?next=`/returnTo on post-login navigation | mitigate | Reject any destination containing `://` or starting with `//`; only navigate to internal leading-slash paths; default `/` (Pitfall 6, D-10). |
| T-3-01 | Elevation of Privilege | customer self-escalates `role` via anon key | mitigate | Enforced by Plan 01's `enforce_profile_role_lock` trigger; PROVEN here by the manual customer-JWT escalation rejection (VALIDATION.md). |
| T-3-11 | Elevation of Privilege | customer writes catalog/content via anon key | mitigate | Existing 0002 `*_admin_write` RLS `using private.is_admin()`; proven by the manual catalog-write-rejected check. |
| T-3-SC | Tampering | npm installs | accept | No new package installs — all deps pre-existing (RESEARCH Package Legitimacy Audit: N/A). |
