<objective>
Build the **live read-layer foundation** that the public components (Plan 03) consume: the single-source-of-truth price formatter, the `catalog.ts` data layer (TanStack Query hooks + snake_case->camelCase mapper + Storage path->public-URL + placeholder helper, with the server-side `is_active` published filter), and the `products.ts` refactor (remove the Vite glob, adapt the `Product` type so `price` is `number | null`, re-export the glob-free metadata from `catalog-data.ts`).

Purpose: Implements the data-access half of PUB-01 (Shop/Home read live Supabase data) and PUB-02 (published-only filter lives server-side in the query). This is the interface-first plan: it DEFINES the contracts (`useProducts`, `useCategories`, `productImageUrls`, `formatPrice`, adapted `Product`) that Plan 03 wires into the UI without re-deriving them.

Output: `client/src/lib/format.ts`, `client/src/lib/catalog.ts`, and a refactored `client/src/data/products.ts`. No component edits here (Plan 03 does those) — so the build stays green by keeping the old `products` array exported until Plan 03 removes the runtime consumers.

CRITICAL: `Product.price` changes from `string` to `number | null`. This is the one breaking type change (RESEARCH Pitfall 5) — handle it here, route ALL rendering through `formatPrice` in Plan 03.
</objective>
