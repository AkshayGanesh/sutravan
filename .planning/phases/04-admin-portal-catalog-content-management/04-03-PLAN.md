<objective>
Build the single admin write data-layer — `lib/admin.ts` — and the public `lib/siteContent.ts` read hook. This is the interface contract every Wave-3 feature plan (products, categories, site content, submissions) consumes, so it is built first and in full: all CRUD functions, Storage upload/remove, slug-collision handling, and TanStack Query mutation hooks that invalidate the public catalog cache.

Purpose: Mirror catalog.ts's snake↔camel boundary symmetrically for writes (Phase 2 decision: map ONCE at the data-layer boundary). Because queryClient.ts sets `staleTime: Infinity`, nothing refetches on its own — every mutation MUST call invalidateQueries so an admin edit appears on the live public Shop with no redeploy (the milestone's core value). Building the full contract here lets the four feature plans run in parallel against stable function signatures instead of exploring the codebase.
Output: lib/admin.ts (product/category/content CRUD + image Storage + mutation hooks) with a round-trip mapping unit test; lib/siteContent.ts public read hook with fallbacks.
</objective>
