<objective>
Build the admin shell — the chrome the whole portal lives in — and wire all `/admin/*` routes behind the existing AdminGuard. Replace the placeholder `Admin.tsx` (which uses the public Layout) with an `AdminLayout` that drops the marketing Navbar/Footer and shows a sidebar (Products / Categories / Site Content / Submissions) plus a slim header (brand wordmark, "View site" link, logout). Create the shared cross-cutting components (ConfirmDialog, plus thin stubs for ImageDropzone and RepeatableRows that feature plans replace) and mount the Sonner Toaster.

Purpose: This is the structural slice — after it, an admin can navigate the portal and reach four section pages, each currently a minimal placeholder. Wiring every route and stub page here (interface-first) means the four Wave-3 feature plans each REPLACE exactly one section page with no App.tsx edits and no route conflicts, so they run in parallel.
Output: AdminLayout + four stub section pages + ConfirmDialog + stub ImageDropzone/RepeatableRows + App.tsx routes + Sonner Toaster.
</objective>
