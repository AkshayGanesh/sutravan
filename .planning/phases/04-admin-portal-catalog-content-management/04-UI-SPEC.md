# Phase 4 — UI Design Contract

> Visual and interaction contract for the Admin Portal (Products / Categories / Site Content / Submissions). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This is an **internal admin tool for a single non-technical owner**, not a public marketing surface. It REUSES the established Sutravan brand tokens and the shadcn/ui primitives already in the repo — it does NOT introduce a new design system. The contract below locks how those existing tokens and primitives are applied inside `/admin`, plus the copywriting the planner/executor must not improvise.

## Spacing Scale

Declared values (multiples of 4 only). Apply via Tailwind spacing utilities (`gap-*`, `p-*`, `space-y-*`).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, repeatable-row inner padding, badge padding |
| sm | 8px | Compact spacing: table cell padding, form-field-to-error gap, chip spacing |
| md | 16px | **Default** spacing: between form fields, card padding, sidebar item padding |
| lg | 24px | Content-area gutters, section padding, gap between form field-groups |
| xl | 32px | Gap between major form sections (e.g. details block vs image block) |
| 2xl | 48px | Page top padding, empty-state vertical centering breathing room |
| 3xl | 64px | Reserved for empty-state hero spacing / large vertical voids |

**Exceptions:**
- Admin header height: **56px** (14 × 4) — standard slim app-bar height.
- Touch targets on phone (D-03): interactive controls (Published toggle, edit/delete icon buttons, image remove [x]) must be **≥ 44px** hit area even when the visual glyph is smaller. Button `icon` size is `36px` (`h-9 w-9`) by default — wrap row actions in a `44px` min touch zone on mobile.
- Product-list row thumbnail: **48px** square (12 × 4).
- Image-dropzone thumbnails: **96px** square (24 × 4) with an 8px grid gap.

## Typography

UI uses Poppins (`--font-sans`) only. **Samarkan serif is NOT used in the admin portal.** Two weights max: regular 400 + semibold 600 (the repo's `font-medium`/`font-bold` map here — use 600 for emphasis, 400 for body; avoid stacking a third weight).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Page title | 24px (`text-2xl`) | 600 (semibold) | 1.2 | Section heading per screen ("Products", "Edit product", "Site content") |
| Section / card heading | 18px (`text-lg`) | 600 (semibold) | 1.2 | Form-section headers, card titles, submission name in detail |
| Body / input | 16px (`text-base`) | 400 (regular) | 1.5 | Form inputs, body copy, submission message, table primary cell text |
| Label / meta | 14px (`text-sm`) | 400 / 600 | 1.4 | Field labels (600), table secondary cells, helper text, dates, badges (400) |

**Rules:**
- Body line-height **1.5**, heading line-height **1.2** (locked).
- Field labels: 14px semibold. Helper/validation text: 14px regular.
- Do NOT use uppercase letter-spacing tracking treatments in admin chrome (those belong to the public marketing UI — `ProductCard`/`Hero`). Admin labels are sentence-case, untracked, for scannability.

## Color

Reuses the locked Sutravan tokens in `client/src/index.css` (HSL custom properties). The admin chrome deliberately leans **calmer than the public site** — accent (gold) is rationed, green is structural.

| Role | Value (token) | Usage |
|------|---------------|-------|
| Dominant (60%) | `--background` = `40 33% 96%` (very light beige) | Content-area background, form surfaces, table background |
| Secondary (30%) | `--card` / `--accent` = `38 44% 85%` (sandalwood beige) | **Sidebar surface**, cards, table header row, section panels — the admin chrome |
| Accent (10%) | `--primary` = `146 32% 24%` (forest green) | Primary action buttons (Save, + New product, + Add), active sidebar item, focused field ring fallback, Published-ON toggle track |
| Gold highlight | `--secondary` / `--ring` = `43 65% 60%` (soft gold) | **Rationed** — focus ring (`--ring`) only, plus the single brand wordmark accent in the header. NOT for buttons or large fills in admin. |
| Destructive | `--destructive` = `0 84% 60%` | Delete buttons, destructive AlertDialog confirm action, oversized-file rejection messaging |

**Accent (forest green) reserved for:**
1. Primary CTAs (the one main action per screen: Save product, + New product, Add category, Save content).
2. Active sidebar nav item.
3. Published-toggle ON state track.
4. Repeatable-row "+ Add" affordance (text/icon).

**Explicitly NOT accent-colored:** secondary/cancel buttons (use `outline` or `ghost` variant), table rows, body text, the majority of the surface. Never "all interactive elements."

**Radius:** `--radius: 0rem` (sharp edges) is the brand signature — admin inherits it. Do not round admin cards/buttons; keep the earthen sharp-edge language.

**Border/divider:** `--border` = `146 15% 85%` for table row dividers, card borders, sidebar separation. `--muted-foreground` for secondary/meta text and disabled labels.

## Component States (default / hover / focus / disabled / loading / empty / error)

> These states are the cross-screen contract. The executor must implement every applicable state per surface — no surface ships with only the happy path.

### Buttons (shadcn `button`)
- **Primary CTA:** `variant="default"` (green), one per screen.
- **Secondary/cancel:** `variant="outline"`. **Destructive:** `variant="destructive"`.
- **Hover:** repo's `hover-elevate` utility (already in `button.tsx`) — do not invent hover colors.
- **Focus:** visible `ring-1 ring-ring` (gold) — keyboard focus must be visible (accessibility).
- **Disabled:** `opacity-50`, no pointer events (shadcn default) — used while a mutation is in flight.
- **Loading:** on submit, swap label for `<Spinner>` + keep width; disable the button. (Reuse `ui/spinner`.)

### Tables / lists (shadcn `table`) — Product list (D-05), Categories (D-15/16), Submissions (D-17)
- **Default row:** thumbnail (48px, products only) · primary text 16px · secondary meta 14px muted · trailing actions.
- **Hover:** subtle row background shift (`--accent`/`muted`), cursor affordance on the whole row where it navigates to edit.
- **Loading:** `Skeleton` rows mirroring the real column layout (no layout shift — mirrors the Phase 2 public-grid skeleton convention). Minimum 4 skeleton rows.
- **Empty:** use shadcn `empty` primitive (see Copywriting empty states per surface).
- **Error:** inline message block (icon + text) + a **Retry** button calling `refetch()` (mirrors the Phase 2 public-shop error pattern, Phase 3 D-14 model).
- **Mobile (`< md`):** each row becomes a stacked `Card` (thumbnail + name + category + price + toggle + actions stacked vertically).

### Forms (shadcn `form` + react-hook-form + Zod) — Product (D-04/06/09), Category (D-16), Site Content (D-18/19)
- **Field default:** label (14px semibold) above input; 16px input; helper text 14px muted below where useful.
- **Focus:** gold ring on the focused input.
- **Disabled:** muted, while submitting.
- **Validation error:** field border → destructive; error message 14px in destructive color directly under the field (inline, never a bare toast for field errors). Email field uses Zod `.email()`; URL fields use Zod `.url()`; price uses numeric/blank.
- **Submit loading:** primary button shows spinner + disables; the whole form is non-interactive during the write.
- **Success/error of the write itself:** Sonner toast (see cross-cutting), NOT inline.

### Published toggle (shadcn `switch`) (D-13)
- **OFF (draft):** track muted/neutral; helper meaning "Draft — hidden from the public site."
- **ON (published):** track green (accent); meaning "Published — live on the Shop."
- **In-flight:** optimistic flip with a subtle spinner/disabled state until the mutation resolves; on error, revert + error toast.
- New products default **OFF/draft** (D-08).

### Image dropzone (D-10, D-11, D-12) — the highest-care surface
- **Default (empty):** dashed-border drop zone, `ImagePlus` icon, copy: "Drag photos here, or click to choose". Subtext: "JPEG, PNG, WebP or HEIC · up to 10 MB each".
- **Drag-over:** border + background emphasis (accent/green border) to confirm the drop target is live.
- **Per-image thumbnail:** 96px square, with a remove **[x]** button (top-right, 44px touch zone on mobile) — `AlertDialog`-free for in-session removals not yet saved; confirm only if removing an already-saved image.
- **Per-image uploading:** thumbnail overlaid with a spinner OR a `progress` bar; the row is not "done" until resolved.
- **HEIC conversion in progress:** thumbnail shows a spinner with the label "Converting…" (HEIC→JPEG runs before upload).
- **Size-guard rejection (`> 10 MB`):** the file never enters the list; show an inline destructive message + error toast: "That photo is too large (max 10 MB). Try a smaller one." (reject BEFORE processing — RESEARCH Pitfall 3.)
- **Unsupported type:** inline destructive message + toast: "That file type isn't supported. Use JPEG, PNG, WebP or HEIC."
- **Conversion failure (HEIC/WASM fails):** clear the stuck spinner; error toast: "Couldn't process this photo — try a JPEG or PNG." (D-11 fallback — never a silent dead spinner.)

### Rich-text editor (TipTap) (D-19) — Our Story body only
- Toolbar: **bold, italic, link, bullet list, ordered list** (the D-19 set) — small icon buttons, ghost variant, active-mark state highlighted.
- All other site-content fields are plain `input`/`textarea` with validation.
- Public render path sanitizes via DOMPurify (security contract — not a visual concern, but the editor's allowed marks must match the sanitizer allow-list).

### Onboarding signal — products missing imagery (CONTEXT specifics)
- In the product list, a row whose `images[]` is empty (the Phase-2-seeded scrub/cream products) shows a **"No photo" badge** (muted `badge`, `ImageOff` icon) in the thumbnail cell instead of an image. This is the owner's natural first task — surface it, do not hide it.

## Copywriting Contract

> Locked copy. The planner/executor must use these strings verbatim (or near-verbatim) so the non-technical owner gets consistent, plain-language guidance. Tone: plain, calm, second-person, no jargon, no slug/HTML/RLS terms surfaced.

### Primary CTAs (one per screen)

| Screen | Primary CTA |
|--------|-------------|
| Product list | **+ New product** |
| Product form (create) | **Save product** |
| Product form (edit) | **Save changes** |
| Categories | **+ Add category** |
| Repeatable rows (benefits/ingredients/tips) | **+ Add** |
| Site content | **Save content** |
| Image dropzone | **Drag photos here, or click to choose** |

### Empty states (shadcn `empty`)

| Surface | Heading | Body + next step |
|---------|---------|------------------|
| Products (none yet) | "No products yet" | "Create your first product to show it on the Shop." → **+ New product** |
| Categories (none yet) | "No categories yet" | "Add a category so you can group your products." → **+ Add category** |
| Submissions (empty — expected until Phase 5) | "No submissions yet" | "Customer customization requests will appear here once the questionnaire is live." (no CTA — read-only) |
| Product image dropzone (no images) | "No photos yet" | "Add product photos so this product looks great on the Shop." |

### Error states

| Surface | Copy (problem + what to do) |
|---------|------------------------------|
| List/data load failure | "Couldn't load this. Check your connection and try again." + **Retry** button (calls `refetch()`) |
| Generic write failure | Toast: "Something went wrong while saving. Please try again." |
| Image too large | "That photo is too large (max 10 MB). Try a smaller one." |
| Unsupported image type | "That file type isn't supported. Use JPEG, PNG, WebP or HEIC." |
| HEIC/processing failure | "Couldn't process this photo — try a JPEG or PNG." |
| In-use category delete (D-15) | "This category has {N} products — move or delete them first." (the friendly translation of the FK `23503` error — never surface the raw DB error) |
| Email field invalid | "Enter a valid email address." |
| URL field invalid | "Enter a valid web address (starting with https://)." |

### Write success toasts (Sonner) — every write surfaces one (D-12 cross-cutting)

| Action | Success toast |
|--------|----------------|
| Product created | "Product saved." |
| Product updated | "Changes saved." |
| Product deleted | "Product deleted." |
| Published toggled ON | "Product is now live on the Shop." |
| Published toggled OFF | "Product hidden from the Shop." |
| Image(s) uploaded | "Photo added." |
| Image removed | "Photo removed." |
| Category created/updated | "Category saved." |
| Category deleted | "Category deleted." |
| Site content saved | "Site content updated." |

### Destructive confirmations (shadcn `AlertDialog` — required on EVERY destructive action, D-12 cross-cutting)

| Action | Dialog title | Body | Confirm button (destructive) | Cancel |
|--------|--------------|------|------------------------------|--------|
| Delete product | "Delete this product?" | "This removes "{name}" and its photos from the Shop. This can't be undone." | "Delete product" | "Cancel" |
| Delete category | "Delete this category?" | "This category will be removed from the Shop tabs. This can't be undone." | "Delete category" | "Cancel" |
| Remove a saved image | "Remove this photo?" | "This photo will be removed from the product. This can't be undone." | "Remove photo" | "Cancel" |

> Confirm buttons use `variant="destructive"`. Cancel uses `outline`/`ghost`. The confirm dialog is a single reusable `components/admin/ConfirmDialog.tsx` wrapper (RESEARCH structure) so the pattern is identical everywhere. In-session (not-yet-saved) image removals may skip the dialog; saved-image removals require it.
