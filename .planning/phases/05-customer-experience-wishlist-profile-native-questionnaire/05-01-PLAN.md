## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser client → Supabase PostgREST (`wishlists`) | Untrusted anon/auth key crosses here; the only real gate is RLS on `wishlists`. |
| logged-out heart tap → `?next=` redirect | Untrusted current-location string feeds the login redirect. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | `wishlists` SELECT (cross-user read) | mitigate | Rely on existing `wishlists_owner_read` RLS (`(select auth.uid()) = user_id`, 0002) — `useWishlist` adds no service-role path; a customer can only ever read their own rows. No schema change this slice. |
| T-05-02 | Tampering / Elevation | `wishlists` INSERT (forge another user's `user_id`) | mitigate | Insert sets `user_id` from `supabase.auth.getUser()` and existing `wishlists_owner_insert` WITH CHECK `(select auth.uid()) = user_id` rejects any forged id server-side. Client value is convenience only. |
| T-05-03 | (open redirect) | logged-out heart prompt + AuthGuard `?next=` | mitigate | Reuse the audited `safeReturnTo()` (Login.tsx) — internal leading-slash paths only; `//` and `://` rejected to `/`. No new sanitizer. |
| T-05-04 | Spoofing | UI heart "saved" state | accept | Optimistic UI is cosmetic; the authoritative state is the RLS-scoped `['wishlist']` query reconciled on `onSettled` invalidate. A faked client state cannot persist a row it has no RLS right to. |
</threat_model>
