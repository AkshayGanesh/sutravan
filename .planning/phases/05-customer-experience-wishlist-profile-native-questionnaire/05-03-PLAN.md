## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser wizard → Edge Function | Untrusted form values + Turnstile token leave the client. |
| client → `?next=`/nav links | Thank-you links are internal literals (/profile, /register) — no untrusted redirect. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-11 | Tampering | logged-in `user_id` on submit | mitigate | The client passes `user.id` for logged-in users, but the authoritative gate is the 0007 WITH CHECK enforced by the Edge Function insert under the caller's JWT (Plan 02 / T-05-05) — a tampered client `user_id` is rejected server-side. |
| T-05-12 | Spoofing / DoS | bot spam on the public form | mitigate | Turnstile widget on the review step + server-side `siteverify` (Plan 02); single-use 300s token reset after failure (Pitfall 3). |
| T-05-13 | Information Disclosure | Turnstile site key in client | accept | `VITE_TURNSTILE_SITE_KEY` is the PUBLIC site key (safe to bundle); the secret stays server-side (Plan 02 T-05-09). |
| T-05-14 | Tampering (XSS via payload) | admin inbox rendering of payload | accept | The admin inbox renders `payload` as `JSON.stringify(...)` inside a `<pre>` (text, no eval/HTML) — structured client values cannot execute. Validation is Zod-shaped (V5). |
</threat_model>
