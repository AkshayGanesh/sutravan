# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5 (Wishlist, Profile, Native Questionnaire).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Nearly everything here is **pre-populated from the existing codebase** (`client/src/index.css`,
> shadcn `components.json`, and established Phase 2–4 component conventions). Phase 5 introduces
> NO new design tokens — it reuses the locked Sutravan brand system and the proven loading/empty/
> error/confirm/toast primitives.

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | shadcn (already initialized) | `components.json` |
| Preset | new-york style, `neutral` base color, `cssVariables: true`, no prefix | `components.json` |
| Component library | Radix UI primitives via shadcn (`client/src/components/ui/*`) | codebase scan |

**Reuse mandate (no net-new visual primitives):**
- States: loading = `Skeleton` mirroring real layout; error = inline `border-destructive/40 bg-destructive/5` block + `Button variant="outline"` Retry calling `refetch()`; empty = `Empty`/`EmptyHeader`/`EmptyTitle`/`EmptyDescription`.
- Destructive actions = `ConfirmDialog`; every write surfaces a Sonner toast (success/error).
- Forms = React Hook Form + Zod + shadcn `Form`/`Field`/`Input`/`Label`/`Select`/`Checkbox`/`RadioGroup`.
- Detail views = shadcn `Dialog` with the `Field` row helper shape from `pages/admin/Submissions.tsx`.

## Spacing Scale

8-point scale (multiples of 4), as already used across Navbar/Submissions/ProductCard.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline label-to-value gaps (`space-y-1`) |
| sm | 8px | Compact element spacing, mobile card list gaps (`space-y-3` ≈ 12 acceptable) |
| md | 16px | Default element / card padding (`p-4`), field stacks |
| lg | 24px | Section spacing (`space-y-6` between page header and content) |
| xl | 32px | Wizard step vertical rhythm, page top/bottom padding on mobile |
| 2xl | 48px | Major section breaks, wizard container vertical padding on desktop |
| 3xl | 64px | Page-level top spacing under fixed Navbar on the questionnaire route |

Exceptions:
- **Touch targets:** the heart toggle (`WishlistButton`) and the navbar heart link must present a **minimum 44×44px hit area** (icon may render smaller; pad the button). This is the only sub-grid value permitted and applies to icon-only controls.
- Tracking/letter-spacing for uppercase eyebrow labels follows the existing brand: `tracking-widest` / `tracking-[0.2em]` on category eyebrows and section labels (not a spacing-scale value, a type detail).

## Typography

Exactly 4 size roles, 2 weight families (regular 400 + medium/semibold 500–600), matching the
existing Poppins/Samarkan usage. Heading line-height tight (~1.2), body relaxed (~1.5).

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body / value | 14px (`text-sm`) | 400 / 500 (`font-medium` for values, prices, field labels) | 1.5 | Default reading text, form field values, submission snippets, prices via `formatPrice` |
| Label / eyebrow | 12px (`text-xs`) | 500 (`font-medium`), `uppercase tracking-wide`/`tracking-widest` | 1.4 | Field labels, category eyebrows, navbar sub-brand, step counter ("Step 2 of 4") |
| Heading | 18–20px (`text-lg` cards / `text-2xl` page heads) | 500–700 (`font-medium`→`font-bold` for h2–h6 sans), serif for page-brand h1 | 1.2 | Product name on wishlist cards (`text-lg`), page titles (`font-serif text-2xl text-primary`), wizard step titles |
| Display | 28px+ (`text-3xl`/`text-4xl`) | serif (Samarkan) | 1.2 | Questionnaire intro/brand heading and the thank-you finale headline only |

**Rules:**
- Page/section titles use `font-serif text-2xl text-primary` (mirror `Submissions.tsx` header) — applies to `/profile` and `/wishlist` page headers and the questionnaire intro.
- h2–h6 are `font-sans font-bold`; body is `font-sans` 400. Never introduce a 3rd weight beyond the regular/medium(+bold-for-headings) set already in `index.css`.

## Color

The Sutravan theme is **locked** in `client/src/index.css` (`:root`). Phase 5 adds NO new colors.
The 60/30/10 split maps to the existing tokens:

| Role | Token / Value | Usage |
|------|---------------|-------|
| Dominant (60%) | `--background` = `hsl(40 33% 96%)` very light beige | Page backgrounds, wizard surface, profile/wishlist page canvas |
| Secondary (30%) | `--card` = `hsl(38 44% 85%)` sandalwood beige | Cards (wishlist product tiles image bg `bg-card`), dialog/popover surfaces, form section panels |
| Accent (10%) | `--secondary` = `hsl(43 65% 60%)` soft gold; `--primary` = `hsl(146 32% 24%)` forest green | See reserved-for list below |
| Destructive | `--destructive` = `hsl(0 84% 60%)` | Destructive actions ONLY |

**Accent reserved for (explicit — never "all interactive elements"):**
- **Primary green (`--primary`):** primary CTA buttons (wizard "Continue"/"Submit", profile "Save"), page titles, product name links, the wishlist count badge background on the navbar heart.
- **Soft gold (`--secondary` / `--ring`):** hover-state color on product names (`group-hover:text-secondary`, existing), focus rings (`--ring` is already gold), and the **filled heart** state (a saved item's heart fills gold/primary to read as "active"). The empty/unsaved heart is `text-foreground/60` outline only.
- The heart toggle is the one net-new accent surface this phase introduces; it must use the existing gold/primary tokens, not a new color.

**Destructive usage (this phase):**
- Wishlist remove: instant optimistic, **no destructive styling escalation** (D-13 says no confirm). The remove control is a neutral/ghost icon button, NOT a red button.
- Account changes (email/password) are not destructive; use primary, not destructive.
- `--destructive` appears only in the inline error block tint (`bg-destructive/5`, `border-destructive/40`) — same as `Submissions.tsx`.

## Interaction Contract (phase-specific)

| Surface | Contract |
|---------|----------|
| Questionnaire focal point | The Display-role serif heading ("Customize your blend") is the primary focal point of the `/questionnaire` route — largest element, Samarkan font, drawn first. The active step's content area is the secondary anchor; the step indicator and "Continue" CTA are tertiary. |
| Wishlist heart on ProductCard | `e.stopPropagation()` + `e.preventDefault()` (keyboard) so it never opens the detail modal (D-09 / Pitfall 7). 44px hit area. Filled gold/primary when saved; outline `text-foreground/60` when not. |
| Wishlist heart on ProductDetail modal | Same toggle, reads/writes the same `['wishlist']` cache so card + modal stay in sync (D-13). |
| Logged-out heart tap | Sign-in toast/prompt → `/login?next=<current>` via existing `safeReturnTo` (D-10). No anonymous wishlist UI. |
| Navbar heart + badge | Count derived from the `['wishlist']` cache (no separate count query — D-12/Pitfall 6). Badge hidden when count is 0. |
| Optimistic toggle feedback | Heart state flips immediately; rollback + error toast on failure (Pattern 3). No spinner on the heart. |
| Wizard step transitions | Validate current step via `trigger()` before advancing; "Continue" disabled or shows inline errors on invalid. Logged-in name/email rendered read-only/disabled (D-08). |
| Turnstile widget | Lazy-loaded CF hosted script, rendered on the review/final step only; reset token after a failed submit (Pitfall 3). Visually a discreet block above the final CTA. |
| Auth-gated routes | `/profile`, `/wishlist` show a spinner while `loading`, then redirect logged-out users to `/login?next=…` (Pattern 6). |
| Responsive | Lists use the established pattern: table on `md+`, stacked bordered cards on mobile (mirror `Submissions.tsx`). Wishlist uses a responsive product grid mirroring the Shop grid classes (no layout shift on load — skeleton grid). |
