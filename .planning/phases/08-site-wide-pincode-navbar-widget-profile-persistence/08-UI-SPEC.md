# Phase 8 — UI Design Contract

> Visual and interaction contract for the site-wide "Deliver to [pincode]" navbar widget (pill + popover). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope reminder (locked upstream, do NOT re-open):** pure location *setter* — format-only `/^\d{6}$/` validation, no network, no Turnstile, no estimate call (08-CONTEXT D-05). Reads/writes the existing Phase 7 `DeliveryProvider` (`{ pincode, setPincode }`) as the single source of truth; profile sync is a silent side-effect (D-03/D-08). This spec locks only the visual + interaction layer on top.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | new-york style, baseColor neutral, cssVariables true (components.json) |
| Component library | Radix (`@radix-ui/react-popover`) via `@/components/ui/popover`, `input`, `button` — all already in repo |
| Icon library | lucide-react |
| Font | Poppins (`--font-sans`) for all widget text; Samarkan (`--font-serif`) is logo/h1 only and is NOT used here |

**Radius note:** `--radius: 0rem` (sharp edges, luxury/earthen feel). All widget surfaces (pill, popover, input, button) render square-cornered. Do not introduce rounded corners.

**Reuse mandate:** Use the existing `Popover` / `PopoverTrigger` / `PopoverContent`, `Input`, and `Button` primitives. No new shadcn blocks are added in this phase.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | (unused this phase) |
| sm | 8px | Pill icon↔label gap (`gap-2`); input→button stack gap (`gap-2`); error/helper top margin (`mt-2`); micro-label bottom margin |
| md | 16px | Popover interior padding (`p-4`, the shadcn default) |
| lg | 24px | (unused this phase) |

Component heights (all multiples of 4):
- Desktop pill / trigger height: **36px** (`h-9`) — aligns with the shadcn Input/Button new-york height.
- Mobile pill / trigger height: **44px** (`h-11`) — matches the existing wishlist/icon touch-target convention in `Navbar.tsx` (`h-11 w-11`) and meets the ≥44px tap-target minimum.
- Pill horizontal padding: **10px** each side is disallowed (not on scale); use **12px** (`px-3`).

Exceptions: none — all values resolve to multiples of 4.

## Typography

Exactly 3 sizes, exactly 2 weights.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Micro-label | 12px (`text-xs`) | 600 (semibold) | 1.2 | Popover heading "Delivery pincode" (uppercase, `tracking-widest`, `text-foreground/50`) — mirrors the "Delivery" label in `DeliveryEstimate.tsx` |
| Body / control | 14px (`text-sm`) | 400 (regular) | 1.5 | Pill label, helper caption, inline error text, input text (desktop) |
| Input (mobile) | 16px (`text-base`) | 400 (regular) | 1.5 | shadcn Input renders `text-base` then `md:text-sm` — 16px on mobile prevents iOS zoom-on-focus |
| Emphasis | 14px (`text-sm`) | 600 (semibold) | 1.5 | The set pincode value inside the pill ("Deliver to **110001**"); the Save pincode button label |

**Weights declared:** Regular **400** + Semibold **600**. No other weights. (The pill label sits at 400 by default; when a pincode is set, the numeric value is rendered at 600 for scannability.)

## Color

60 / 30 / 10 split mapped to the Sutravan theme (HSL tokens from `index.css`):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(40 33% 96%)` light beige (`--popover` / `--background`) | Popover surface, pill background (transparent → inherits page) |
| Secondary (30%) | `hsl(146 32% 24%)` forest green (`--primary`) | Save pincode button fill (`bg-primary`), pill MapPin icon, set-value emphasis text (`text-primary`), default pill/label ink |
| Accent (10%) | `hsl(43 65% 60%)` soft gold (`--secondary` / `--ring`) | Reserved — see list below |
| Destructive | `hsl(0 84% 60%)` (`--destructive`) | Inline format-validation error text ONLY |

**Accent (soft gold) reserved for — explicit list, nothing else:**
1. Focus-visible ring on the pincode `Input` (`--ring` is already gold — `focus-visible:ring-ring`).
2. Hover color on the pill trigger (`hover:text-secondary`) — matches every other nav item's hover.
3. Hover fill on the Save pincode button (`hover:bg-secondary hover:text-primary`) — matches the `DeliveryEstimate` submit button.

Accent is NOT used for default button fill, borders, or resting states.

**Pill border:** subtle, `border border-border/60` (border token `hsl(146 15% 85%)`), sharpening to `hover:border-secondary` on hover so the pill reads as an interactive chip distinct from the icon-only nav buttons.

| Element | Copy |
|---------|------|
| Primary CTA (popover submit) | **Save pincode** |
| Pill — empty state (desktop, `md+`) | **Set pincode** |
| Pill — empty state (mobile, `<md`) | MapPin icon + **Set** (compact) |
| Pill — set state (desktop) | **Deliver to 110001** (value at weight 600) |
| Pill — set state (mobile) | **110001** (MapPin icon + 6-digit value, no prefix) |
| Popover heading (micro-label) | **Delivery pincode** |
| Popover helper caption | **We'll use this to estimate delivery across the site.** |
| Input placeholder | **6-digit pincode** |
| Error state (invalid format) | **Enter a valid 6-digit pincode.** (verbatim match to `DeliveryEstimate.tsx` — one error voice across the app) |
| Destructive confirmation | none — this phase has NO destructive actions. Changing the pincode is a non-destructive overwrite (retype + Save pincode); no clear button, no confirm dialog. |

- No success toast on save (D-08 silent-degrade posture); the pill updating to "Deliver to 110001" is the confirmation.

## Component & Interaction Contract

The load-bearing part of this phase. One new consumer component (Claude's-discretion filename, e.g. `client/src/components/delivery/DeliveryPincodePill.tsx`) that calls `useDelivery()` and renders a `Popover`.

### Pill (PopoverTrigger)

- Structure: `inline-flex items-center gap-2` → `<MapPin size={18} strokeWidth={1.5} />` + label span.
- Icon: lucide **MapPin** (location semantics; distinct from the `User`/`Heart`/social icons already in the cluster). `strokeWidth={1.5}` to match nav convention.
- Height: `h-9` desktop, `h-11` mobile; padding `px-3`; `border border-border/60`; square corners.
- Resting ink: `text-primary` (green). Hover: `hover:text-secondary hover:border-secondary`, `transition-colors duration-300` (matches nav).
- **Empty vs set (D-06):** label is derived from `pincode` — `null` → empty copy; non-null → "Deliver to {pincode}" (desktop) / "{pincode}" (mobile), value span at `font-semibold`.
- Truncation: not required — the value is a fixed 6 digits; the desktop prefix "Deliver to " is static. No ellipsis logic needed.
- `aria-label`: "Set delivery pincode" (empty) / "Delivery pincode: {pincode}, change it" (set).

### Popover (PopoverContent)

- `align="end"`, `sideOffset={8}`, width `w-72` (default), `p-4`, `bg-popover`, sharp corners (inherits). Radix collision handling keeps it inside the viewport on mobile.
- Vertical layout (stacked, `space-y-3` or `flex flex-col gap-2`):
  1. Micro-label heading: "Delivery pincode" (`text-xs uppercase tracking-widest text-foreground/50`).
  2. Helper caption: "We'll use this to estimate delivery across the site." (`text-sm text-foreground/70`).
  3. **A `<form>`** wrapping: the `Input` (full width) then the Save pincode `Button` (full width, `mt-2`). Wrapping in a form makes **Enter submit** work natively.
  4. Inline error slot below the input (conditionally rendered).
- Input: `inputMode="numeric"`, `maxLength={6}`, `placeholder="6-digit pincode"`, `onChange` strips non-digits (`e.target.value.replace(/\D/g, "")`) — identical sanitization to `DeliveryEstimate.tsx`. Initial value prefilled from current `pincode`.
- Save pincode button: `type="submit"`, full width, `bg-primary text-primary-foreground py-3 px-5 text-sm uppercase tracking-wider font-semibold hover:bg-secondary hover:text-primary transition-colors duration-300` — same visual language as the estimator's submit button.

### Interaction states

| State | Trigger | Behavior |
|-------|---------|----------|
| Idle (closed) | default | Pill shows empty or set label per `pincode`. |
| Open | click / Enter / Space on pill | Popover opens; Radix auto-focuses the Input; input prefilled with current pincode, caret ready. |
| Typing | keystrokes | Non-digits stripped; capped at 6 chars; any visible error clears on change. |
| Invalid submit | Save pincode / Enter with value not matching `/^\d{6}$/` | Show inline error "Enter a valid 6-digit pincode." (`mt-2 text-sm text-destructive`); popover stays open; NO network, NO `setPincode`. |
| Valid submit | Save pincode / Enter with 6 digits | Call `setPincode(value)`; close popover; pill re-renders to "Deliver to {value}". No toast. (Provider handles localStorage + best-effort silent profile write per D-03/D-08.) |
| Cancel | Escape / click-outside | Popover closes with no change; on next open, local input resets to the current `pincode` (discard unsaved edits). |

### Focus / keyboard (accessibility)

- **Enter** inside the input submits the form (validate → set → close). **Space/Enter** on the focused pill opens the popover (Radix default button semantics).
- **Escape** closes the popover and returns focus to the pill trigger (Radix default).
- Click-outside closes (Radix default).
- Focus ring: `focus-visible:ring-1 focus-visible:ring-ring` (gold) on the input — the shadcn Input default; do not remove.
- The popover traps nothing beyond Radix defaults; the only focusable elements are the input and the Save pincode button.

### Placement & responsive (resolves D-07)

- **Single mount point on all breakpoints:** the pill is the **first item** in the existing navbar right-cluster (`Navbar.tsx` L87, `flex items-center space-x-3`), rendered before the Instagram icon so the delivery utility reads as primary.
- **Breakpoint switch** uses the existing `md` (768px) boundary already governing the nav:
  - `<md` (mobile): compact pill — MapPin + `{pincode}` (or MapPin + "Set" when empty), `h-11`.
  - `md+` (desktop): labeled pill — "Deliver to {pincode}" / "Set pincode", `h-9`.
  - Implement via a `hidden md:inline` / `md:hidden` label swap on the same trigger (icon always visible).
- **Hamburger Sheet:** the pill is **NOT** duplicated inside the mobile `Sheet` (L214+). Rationale: the top-bar pill is already reachable in one tap on every page without opening the menu, satisfying "set from anywhere"; a popover-inside-a-sheet is an awkward nested-overlay pattern and a second source of the same control. Keep the Sheet focused on navigation.
- The pill must not regress the existing cluster on narrow screens: the Email icon is already `hidden sm:block`; the compact mobile pill (~72–84px) fits alongside the remaining icons at ≥360px.

### State source (no visual invention)

- The widget owns NO pincode state of its own beyond the transient input string. `pincode` and `setPincode` come from `useDelivery()`; the Phase 7 `DeliveryEstimate` consumer sees every change automatically (SC2 two-way sync). Do not add a second context, cache, or localStorage key.
