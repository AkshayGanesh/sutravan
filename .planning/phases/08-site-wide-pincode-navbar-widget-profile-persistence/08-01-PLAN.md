<objective>
Ship the site-wide navbar pincode setter (DLVR-09) as a complete vertical slice: a
"Deliver to [pincode]" pill + popover that reads and writes the EXISTING Phase 7
`DeliveryProvider` context (`{ pincode, setPincode }`). Setting the pincode anywhere in
the navbar flows through the shared context, so the Phase 7 product-detail estimator sees
the same value with zero changes (SC2). The pill is a pure location setter — format-only
`/^\d{6}$/` validation, NO network, NO Turnstile, NO estimate call (D-05). Persistence to
localStorage is already handled by the existing `setPincode` (SC3, anonymous path).

Purpose: Deliver "set your pincode from anywhere" (SC1) and the shared-source-of-truth
sync (SC2) without touching provider internals — the pill is a new consumer only.
Output: `DeliveryPincodePill.tsx` (new) mounted in `Navbar.tsx`.
</objective>

## Phase Goal (MVP user story)

Derived faithfully from the ROADMAP Phase 8 goal + the 4 success criteria (the ROADMAP
Goal line is a capability statement, reformatted into the three-slot user story without
adding scope):

**As a** Sutravan shopper, **I want to** set or change my delivery pincode from a navbar
widget on any page — with the choice remembered site-wide (and tied to my account when I'm
logged in), **so that** I never re-enter it between pages or devices and every delivery
estimate reflects where I actually am.

**This plan delivers the navbar-setter slice:** an anonymous or logged-in visitor can set
their pincode from the navbar on any page; it persists (localStorage, via the existing
provider) and immediately drives the product-detail estimator.
