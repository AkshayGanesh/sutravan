<objective>
Ship the pure, test-first foundation the Rate Slabs editor is built on: the Zod
validation contract (`rateSlabsSchema`) and the two data-shaping functions that
convert between the 20 `delivery_rate_slabs` rows and the grid's form shape
(`mapSlabsToForm`, `expandFormToRows`). No supabase client, no React — a plain
module unit-tested in the node env, mirroring the existing `deliverySchema.ts`
sibling (Phase 9).

This encodes the SC3 validation rules (cost ≥ ₹1, ETA min ≤ max) and the D-06
per-zone-ETA-writes-to-all-4-cells expansion so the UI plan (10-02) only wires
inputs to an already-proven contract.

Purpose: Interface-first — define + prove the contract before any consumer
exists, so the page in 10-02 imports tested logic instead of re-deriving it.
Output: `client/src/pages/admin/rateSlabsSchema.ts` + its Vitest suite.
</objective>
