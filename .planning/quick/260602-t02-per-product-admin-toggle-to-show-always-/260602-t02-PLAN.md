<objective>
Add a per-product admin toggle that controls whether the fixed safety note "Always patch test first."
appears on the public product detail view. The toggle lives on the admin product EDITING page
(ProductForm) per the user's explicit request; when ON, the note shows on that product's public detail;
when OFF, nothing renders.

Purpose: Lets the owner decide per product whether to surface the patch-test caution, without code
changes or redeploys — managed entirely through the admin portal (the milestone's core value).

Output:
- New migration 0010 adding `show_patch_test_note boolean not null default false` to `products`.
- `showPatchTestNote` wired end-to-end: catalog.ts public read mapper, admin.ts write mappers + list
  columns, a visible toggle on ProductForm, and a conditional render in ProductDetail.

THIS IS THE SAME SHAPE as the just-shipped out-of-stock toggle (quick task 260602-c2y, migration 0008),
with three intentional differences — read before writing any code:

1. DEFAULT POLARITY IS FALSE, NOT TRUE. The note is opt-in: `not null default false` so all existing
   rows stay OFF (no backfill, no surprise note appearing everywhere). in_stock used default true; this
   column uses default false. Do not blindly copy the `default true` from 0008.

2. TOGGLE LOCATION IS THE FORM, NOT THE LIST. in_stock's visible control lives on ProductsList and is
   merely carried as a hidden value through ProductForm. This toggle is the OPPOSITE: it is a VISIBLE
   Switch FormField on ProductForm (mirror the existing "Published"/isActive Switch block at the bottom of
   ProductForm, lines ~397-419). Do NOT add a column/toggle to ProductsList — the user explicitly placed
   this on the product editing page, and a list control is out of scope here.

3. THIS CHANGES EXISTING PUBLIC BEHAVIOUR. ProductDetail.tsx today renders "Always patch test first."
   UNCONDITIONALLY for EVERY product (currently around lines 191-193, inside the shelf-life/batch-note
   block). After this change that line MUST be gated on `product.showPatchTestNote` — i.e. it shows only
   when the flag is true and renders nothing when false. This is a deliberate behaviour change from
   "always shown" to "shown only when the owner opts in"; existing products default OFF, so the note
   disappears from products until the owner enables it. The note text stays a hardcoded constant
   "Always patch test first." — it is NOT admin-editable and is NOT a new DB text column.

LIKE 0008: this is a DISPLAY flag, NOT a visibility flag. The column appears in NO RLS policy, and
catalog.ts's fetchProducts applies NO `.eq('show_patch_test_note', ...)` filter — the product's public
readability is completely unchanged. Keep the existing `.eq('is_active', true)` exactly as-is.
</objective>
