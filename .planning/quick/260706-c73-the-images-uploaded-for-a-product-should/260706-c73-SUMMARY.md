# Quick Task 260706-c73: Reorderable Product-Image Thumbnails Summary

**Committed product-image thumbnails in the admin Photos section are now drag-reorderable via a grip handle (framer-motion Reorder), emitting the new order through the existing `onChange` so array order — and thus the primary/gallery image order on the public shop — is under the owner's control.**

## Performance

- **Duration:** ~8 min
- **Tasks:** 1 of 2 executed (Task 2 is a human-verify checkpoint — pending)
- **Files modified:** 1

## Accomplishments
- Committed thumbnails wrapped in a `Reorder.Group` (`as="ul"`, `axis="x"`, `values={value}`, `onReorder={onChange}`) — reordering persists by array order, no backend/schema change.
- Each committed tile extracted into `ReorderableThumb` so `useDragControls()` is called once per item at the top level (never inside `.map`), mirroring `RepeatableRow` in `RepeatableRows.tsx`.
- New `GripVertical` handle (bottom-left chip) with `onPointerDown={(e) => controls.start(e)}`, `cursor-grab touch-none`, and `aria-label={`Reorder photo ${index + 1}`}`; handle-only drag (`dragListener={false}`) keeps the X remove click and mobile page-scroll from being hijacked.
- Pending/uploading tiles remain non-reorderable and render after the committed items, preserving the identical single flex-wrap row.
- Untouched: upload pipeline (`handleOneFile`/`handleFiles`), `savedRef` snapshot, `requestRemove`/`confirmRemove`/`removePath`, `ConfirmDialog`, `thumbUrl`, and the drop zone.

## Decisions Made
- Wired `onReorder={onChange}` directly (no id map): Storage paths are unique and stable and `onChange` already accepts `string[]`, so the reordered path array is exactly what the RHF `imagePaths` field wants. This is simpler than the `RepeatableRows` id-bookkeeping approach, which only exists there because rows can be empty/duplicate.
