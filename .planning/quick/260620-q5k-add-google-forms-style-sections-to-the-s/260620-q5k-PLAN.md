# Quick Task 260620-q5k: Skin Guide sections + progressive (one-at-a-time) wizard

## Goal

Group Skin Guide questions into admin-managed **sections** and render the public
questionnaire **one section per step** (Back/Next, progress bar, Submit on last),
so customers aren't shown every question at once.

## Decisions (locked — see CONTEXT.md)

1. Full sections CRUD: `questionnaire_sections` table + `section_id` FK on questions.
2. Ungrouped questions → auto trailing **"More questions"** section. Empty sections omitted.
3. Wizard: progress bar + "Section x of N" counter + Back/Next + validation-gated Next.

## Tasks

### T1 — DB migration `0013_questionnaire_sections.sql`
- New table `public.questionnaire_sections` (id, title, description, sort_order, created_at, updated_at).
- `alter table public.questionnaire_questions add column section_id uuid references public.questionnaire_sections(id) on delete set null`.
- Index on `(sort_order)` for sections; index on `questionnaire_questions(section_id)`.
- RLS: enable + public read + admin write (mirror 0012 policies exactly).
- No seed rows (existing questions stay ungrouped → auto bucket).
- Apply live: `echo y | ./node_modules/.bin/supabase db push --linked`.
- verify: `supabase migration list --linked` shows 0013 applied.
- done: sections table exists live; questions have nullable section_id.

### T2 — Data layer `client/src/lib/questionnaire.ts`
- Add `section_id: string | null` to `QuestionnaireQuestion` + `QUESTION_SELECT`.
- Add `QuestionnaireSection` type + `useQuestionnaireSections()` (key `["questionnaire","sections"]`, ordered by sort_order).
- Add pure `groupIntoSections(sections, questions)` → ordered `{ section, questions }[]`,
  ungrouped questions appended as a synthetic "More questions" group; groups with 0 questions dropped.
- verify: `npm run check` passes.
- done: helpers exported; payload/submission shape unchanged (still snapshots into payload.answers).

### T3 — Public wizard `client/src/pages/Questionnaire.tsx`
- Fetch sections alongside questions; build steps = About + one per non-empty group + Review (+ Thank-you).
- Per-step validation: About → name/email; each section step → that group's question ids; Submit on final section's "Next" position is the Review step (keep existing Review + Turnstile).
- Add progress bar + contextual label ("Section i of G" on section steps).
- verify: `npm run check`; Playwright walk-through.
- done: only the current section's questions render; Back/Next move between sections; required gates advancement; submit works.

### T4 — Admin sections CRUD + question→section assignment
- `client/src/lib/admin.ts`: `SectionFormValues`, `fetchAdminSections`, `useAdminSections`,
  `useUpsertSection`, `useDeleteSection` (invalidate `["questionnaire"]`). Add `section_id` to
  `AdminQuestionRow`/`ADMIN_QUESTION_COLUMNS` and write it in `useUpsertQuestion`.
- New page `client/src/pages/admin/SectionsList.tsx` (mirror QuestionsList: table + Add/Edit dialog with
  title, description, display order; delete via ConfirmDialog — note questions move to "More questions").
- `AdminLayout.tsx`: add "Sections" nav item (after "Skin Guide"); `App.tsx`: add `/admin/sections` route.
- `QuestionsList.tsx`: add a "Section" select (options from `useAdminSections` + "No section") to the
  question form; persist `sectionId`.
- verify: `npm run check`; Playwright: create a section, assign a question, see it group.
- done: owner can CRUD sections and assign questions; public form reflects it after invalidation.
