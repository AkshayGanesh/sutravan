# Quick Task 260620-pt8: Fix Skin Guide edit-question modal re-render & save-once bug

## Problem

In the admin Skin Guide editor (`client/src/pages/admin/QuestionsList.tsx`), the
Edit/Add question modal loses input focus after the first keystroke, and a single
Save click does not persist the question (a second click is required).

## Root cause

`QuestionFormDialog` is a React component **defined inside** the `QuestionsList`
component body and rendered as `<QuestionFormDialog />`. On every render of
`QuestionsList`, `QuestionFormDialog` is a brand-new function identity, so React
unmounts and remounts the entire dialog subtree (including all `<Input>` fields)
rather than reconciling it.

`const fieldType = form.watch("fieldType")` (RHF `watch`) re-renders
`QuestionsList` on **every** form field change — i.e. every keystroke. So the
first character typed triggers a parent re-render → dialog remount → focus loss,
and the same mid-interaction remount swallows the first Save click.

## Fix

1. Replace `form.watch("fieldType")` with `useWatch({ control, name })` so field
   subscription does not force a root re-render of the list on every keystroke.
2. Stop defining `QuestionFormDialog` as a nested component. Render the dialog as
   a stable inline JSX element (`const questionFormDialog = (...)`) so React
   reconciles it in place instead of remounting it on each parent render.

## Tasks

- **T1** — `client/src/pages/admin/QuestionsList.tsx`: import `useWatch`; switch
  `fieldType` to `useWatch`; convert `QuestionFormDialog` function into an inline
  JSX element and replace its 3 `<QuestionFormDialog />` usages.
  - verify: `npm run check` passes; modal keeps focus while typing; one Save click persists.
  - done: typing a full label in one go works; single Save click saves the question.

## Validation

field (focus retained, full text entered), click Save once → toast "Question
saved" and the list reflects the change.
