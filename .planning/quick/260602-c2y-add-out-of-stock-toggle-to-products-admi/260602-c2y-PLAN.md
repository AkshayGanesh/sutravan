<objective>
Add a per-product "Out of stock" toggle to the admin products page. The owner can mark a product
as currently unavailable WITHOUT delisting it: the product stays on the public Shop (customers still
see it exists) but is clearly shown as unavailable.

Purpose: Lets the owner signal temporary unavailability (e.g. a batch sold out) without hiding the
product or touching code — a distinct intent from the existing draft/publish (is_active) toggle.

Output:
- New migration 0008 adding `in_stock boolean not null default true` to `products`.
- `inStock` field exposed end-to-end: catalog.ts public read mapper, admin.ts write hook + list columns,
  admin products list toggle, public ProductCard + ProductDetail "unavailable" UI.

CRITICAL DISTINCTION — read before writing any code:
- `is_active` (draft/publish) controls VISIBILITY. Migration 0005's RLS policy
  `products_public_read ... using (is_active = true)` makes drafts UNREACHABLE on the public path.
- `in_stock` is the OPPOSITE intent: an out-of-stock product MUST remain publicly readable and visible.
  Therefore the new column MUST NOT appear in any RLS policy, and `fetchProducts` in catalog.ts MUST NOT
  filter on it (it keeps only `.eq('is_active', true)`). Out-of-stock products are still `is_active = true`
  and still returned by the public read path; the "unavailable" state is purely a client-side render flag.

Polarity choice (justified): use `in_stock` (default true), NOT `is_out_of_stock`. This mirrors the
existing `is_active boolean not null default true` convention exactly — same positive polarity, same
default-true so all 28 existing rows become in-stock automatically with no data backfill. "Out of stock"
is the negation `!inStock`, computed at render (just as drafts are the negation of is_active).
</objective>
